## Roles and configuration

| Role | Env var | What it does |
| --- | --- | --- |
| Issuer / lender | `PRIVATE_KEY` | Deploys the contracts, writes the KYC attestation, owns the loan token (sUDT owner), owns the vault lock, receives repayment. |
| Borrower | `BORROWER_PRIVATE_KEY` | Owns the RWA asset, deposits it, receives the loan, repays. |

Loan terms come from `LENDING_BORROW_AMOUNT`, `LENDING_REPAY_AMOUNT` and
`LENDING_TERM_SECONDS` (defaults 1000 / 1100 / 3600). They are baked into the
loan type script args at deposit time. The loan token is the testnet sUDT with
the issuer as owner, so the issuer mints it in the borrow tx.

## Verifying independently

You do not need to trust the table above:

1. Open each transaction link and check it is committed on testnet.
2. Check the contract code hashes: `npm run build:contracts && npx ts-node
   scripts/deploy/verify_code_hashes.ts` hashes the locally built binaries and
   compares them with the code hashes above. They must match, since the
   scripts are referenced by data hash. (The build must use the pinned Rust
   1.89.0 toolchain for the bytes to be identical.)
3. Follow the chain: the deposit tx spends the asset cell and the attestation
   cell; the borrow tx spends the loan cell and creates the loan-token cell
   for the borrower; the repay tx pays the lender; the release tx creates an
   asset cell with the same type script locked by the borrower.
4. Fetch any transaction from RPC:
   `curl -s -X POST -H 'content-type: application/json' https://testnet.ckb.dev/rpc -d '{"id":1,"jsonrpc":"2.0","method":"get_transaction","params":["<hash>"]}'`.
